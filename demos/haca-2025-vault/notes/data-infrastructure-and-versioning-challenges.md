# Data Infrastructure and Versioning Challenges

The data infrastructure for the modelling project is separated into three main areas for information governance and performance. Data storage and processing occur in a secure, CSU-provisioned Azure environment, utilizing Databricks instead of SQL to reduce pipeline run times from four days to a more manageable duration. Compute is handled via Docker containers. Results, dashboards, and reports are hosted on a separate internet-connected server accessible to hospitals and NHS entities, but this server contains no raw data to maintain security. Development artifacts, such as notebooks and scripts, are managed on laptops with an emphasis on tidiness and reusability.

Managing model versioning over a development period of more than two years presents a significant challenge. The team faces a strategic choice between an 'Apple' approach (forcing upgrades and breaking older software compatibility) and a 'Microsoft' approach (supporting legacy versions for extended periods). Currently, the team leans towards the Microsoft model to ensure that existing hospital plans and billion-pound investments remain valid and reproducible. Managing the scale of data and model parameters leads to an accretion of data storage requirements, as data is often versioned by creating full copies. Similarly, as models are iterated for various purposes, parameters accumulate, making it difficult to manage and understand the vast number of iterations and scenarios.
